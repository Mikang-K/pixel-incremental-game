# 왼손 키보드 화면 조작 설계안

작성일: 2026-11-23. 상태: 사용자 구현 요청에 따라 적용했다. 검증 결과와 미확인 범위는 수정 계획의 구현 결과에 기록했다.

## 목적과 범위

마우스 휠이 고장 난 상태에서도 왼손으로 그림을 확대, 축소하고 볼 위치를 옮길 수 있게 한다. 오른손 마우스는 원하는 픽셀을 찍는 데 집중한다. 사용자가 요청한 목적과 계획 작성 범위는 확정이며, 아래 키 배치와 속도는 작성자의 제안이다.

## 구현 전 구조와 접근 비교

- `js/ui.js`의 `cam`, `clampCam()`, `zoomAt()`, `fit()`이 화면 위치와 배율을 관리한다. 휠은 커서를 중심으로 확대하고, 오른쪽 또는 가운데 버튼과 `Space+끌기`는 그림을 이동한다.
- 기존 키보드 처리는 `Space`뿐이다. `#view`는 현재 Tab으로 선택할 수 없다. 설정 창은 `<dialog>`이며 저장 문자열 입력용 `<textarea>`가 있다.
- 기존 프레임 루프와 카메라를 재사용하는 방식을 제안한다. 키를 누르고 있는 시간에 맞춰 부드럽게 조작할 수 있고, 새 라이브러리가 필요 없다.
- `keydown` 반복만으로 일정 거리씩 옮기는 방식은 운영체제의 반복 지연과 속도에 영향을 받는다. 별도 카메라 모듈이나 입력 라이브러리 도입은 이번 변경 규모에 비해 범위가 크다.

## 제안 조작

| 키 | 동작 |
|---|---|
| `W`, `A`, `S`, `D` | 위, 왼쪽, 아래, 오른쪽 영역을 보기 |
| `Q` / `E` | 축소 / 확대 |
| `Shift` + 이동 키 | 2배 빠르게 이동 |
| `F` | 그림 전체가 보이는 배율과 위치로 복귀 |

- 이동과 확대, 축소는 누르고 있는 동안 계속한다. `F`는 처음 누를 때 한 번만 실행한다. 서로 반대인 키는 상쇄하고, 대각선 이동의 총속도는 직선과 같게 한다.
- `W`는 그림의 위쪽 영역을 보는 방향이다. 따라서 그림 자체는 화면에서 아래로 움직인다. `A`도 같은 기준으로 왼쪽 영역을 보여 준다.
- 커서가 그림 화면 안에 있으면 그 위치를 중심으로 확대, 축소한다. 밖에 있으면 화면 중앙을 중심으로 한다. `F`를 누른 프레임에는 다른 카메라 입력보다 전체 보기를 우선한다.
- 시작값은 초당 화면 600px 이동, 빠른 이동 2배, 확대 배율 초당 2배다. `CONFIG.ui`에 모으고 실제 브라우저 조작감 확인 후 조정한다. 프레임당 이동 시간은 최대 0.05초로 제한한다.

## 입력과 붓의 안전 조건

- 시작 시 `body`에 포커스가 있거나 그림 캔버스에 포커스가 있을 때 동작한다. 캔버스에 `tabindex="0"`을 추가하고 클릭 시 포커스를 준다. 기존 `:focus-visible` 스타일을 사용한다.
- 설정 창이 열렸거나 다른 버튼, 입력창, 편집 가능한 요소에 포커스가 있으면 화면 단축키를 받지 않는다. `Tab`, 버튼의 `Enter`와 `Space`, 입력과 복사, 붙여넣기는 원래 동작을 유지한다.
- `KeyboardEvent.code`로 키의 물리적 위치를 판별해 한글 자판 상태에서도 같은 위치를 사용한다. 실제 IME 조합 중인 이벤트와 `Ctrl`, `Alt`, `Meta` 조합은 제외한다. `Shift`는 이동 가속에만 사용한다.
- 실제 처리하는 게임 키에만 `preventDefault()`를 적용한다. 기존 `Space+끌기`는 `body`와 캔버스 양쪽 포커스에서 계속 동작하게 한다.
- 칠하기 또는 마우스 화면 이동을 시작하면 카메라 키 상태를 비운다. 드래그 중 새로 누른 카메라 키도 무시한다. 마우스를 놓은 뒤 키를 다시 눌러 화면을 조작한다. 이동만으로 픽셀을 칠하거나 이전 붓 위치에서 긴 선을 잇지 않는다.
- 키를 놓으면 즉시 멈춘다. 창 포커스 상실, 탭 숨김, 포커스가 게임 밖으로 이동, 설정 창 열기, 새 게임 시작 또는 저장 불러오기 때 누른 키와 드래그 상태를 해제한다. 단축키 조합이나 조합 입력으로 전환될 때도 누른 카메라 키를 정리한다.
- 커서는 화면 좌표로 보관하고 카메라 변경 뒤 그림 좌표를 다시 계산한다. 커서를 움직이지 않고 확대하거나 이동해도 붓 미리보기와 실제 클릭 위치가 일치해야 한다.
- 완료 그림도 탐색할 수 있다. 완료 상태를 나타내는 `finishedShown`을 카메라 단축키 차단 조건으로 사용하지 않는다.

## 변경 범위와 제외 항목

- 제품 변경: `js/ui.js`, `js/config.js`, `index.html`, `README.md`.
- 검증 추가: `tests/ui.test.js`. 기존 `node:test`를 사용한다. 테스트 목적으로 게임의 공개 API를 늘리거나 카메라 구조를 분리하지 않는다.
- 화면 안내, 접근성 설명, README에 같은 단축키를 적는다. 기존 휠, 마우스 드래그, 미니맵 조작은 유지한다.
- 게임 규칙, 포인트, 강화, 그림 데이터와 저장 형식은 바꾸지 않는다. 기존 저장의 변환이나 초기화가 필요 없는 범위다.
- 키 재지정 화면, 키보드로 픽셀 찍기, 붓 크기 단축키, 실행 취소와 별도 화면 버튼은 이번 범위에서 제외한다.

## 완료 기준

휠 없이 `E`로 원하는 위치를 확대하고, `WASD`로 이동한 뒤 마우스로 해당 픽셀을 정확히 칠하고, `Q`로 축소하거나 `F`로 전체 보기에 돌아올 수 있다. 설정 입력과 브라우저 단축키를 방해하지 않고, 창 전환 뒤 혼자 움직이거나 칠해지는 일이 없어야 한다. 기존 Node 검사와 실제 브라우저 조작 확인을 모두 통과해야 구현 완료로 판단한다.
