# 색을 잃은 캔버스: 설계 문서

날짜: 2026-11-20
상태: 검토 대기

표기: (결정)은 사용자가 정한 것, (내 판단)은 작성자가 기본값으로 정한 것으로 바꿔도 된다.

## 1. 의도

회색으로 바랜 그림을 픽셀 한 칸씩 되살리는 인크리멘탈 게임. 진행도를 숫자가 아니라 완성되어 가는 픽셀 그림으로 보여 주는 것이 핵심이다. 방치하고 돌아왔을 때 그림이 찬 만큼이 곧 보상이다.

## 2. 목표, 하지 않는 것, 실패 조건

목표
- (결정) PC 브라우저에서 플레이.
- (결정) 일반적인 인크리멘탈 흐름: 초반 클릭, 자동화, 강화, 프레스티지, 오프라인 진행.
- (결정) 첫 버전을 끝까지 보는 데 2시간 이상.
- (결정) 그림은 작성자가 만들되, 나중에 사용자가 보유한 그림을 넣을 수 있는 구조.

첫 버전에서 하지 않는 것 (내 판단)
- 모바일 화면 대응, 소리, 수익화, 서버와 계정, 다국어.
- PNG 가져오기 기능 자체. 형식만 준비한다 (6장).
- 64x64 이상 해상도.

실패 조건
- 한 번의 구매나 완성까지 아무 선택 없이 3분 넘게 기다리기만 하는 구간이 있다.
- 완성된 그림이 무엇인지 알아볼 수 없다.
- 비용, 배율 같은 숫자가 코드 여기저기에 박혀 있어 조정이 어렵다.

## 3. 화면

한 화면, 최소 폭 1280px 기준.

- 가운데: 캔버스. 현재 그림을 정수 배율로 확대해 그린다. 안 칠한 칸은 회색 음영(원래 색의 밝기만 남긴 회색), 칠하는 중인 칸은 진행도만큼 색이 차오른다.
- 캔버스 위: 요정. 2x2 화면 픽셀 크기의 밝은 점이 목표 칸으로 이동해 머문다. 종류별로 색이 다르다.
- 위쪽 띠: 물감 방울 보유량, 초당 획득량, 현재 그림 이름과 진행률.
- 오른쪽 패널: 탭 3개. 요정, 강화, 눈(프레스티지 강화).
- 아래쪽 띠: 갤러리. 완성한 그림의 축소판이 걸리고, 올리면 이름과 보너스가 보인다.
- 설정 버튼: 저장 내보내기, 가져오기, 초기화.

글자는 한글, 가운뎃점은 쓰지 않는다.

## 4. 규칙

### 4.1 칠하기

- 칸마다 필요한 작업량이 있다. 그림이 뒤로 갈수록 커진다.
- 칸을 클릭하면 클릭 힘만큼 작업량이 찬다. 누른 채 끌어도 된다.
- 칸이 다 차면 색이 돌아오고 물감 방울을 준다.
- 모든 칸이 차면 그림이 완성되어 갤러리에 걸리고 다음 그림으로 넘어간다.

### 4.2 요정 (자동화)

물감 방울로 고용한다. 값은 살수록 지수로 오른다.

| 요정 | 역할 |
|---|---|
| 붓 요정 | 한 칸씩 꾸준히 칠한다. 가장 싸다. |
| 롤러 요정 | 가로로 이어진 3칸을 동시에 칠한다. |
| 분무 요정 | 느리지만 3x3 범위를 한꺼번에 칠한다. |

요정은 안 칠해진 칸 중 가까운 곳으로 간다. 계산은 요정 종류별 초당 작업량 합으로 하고, 화면의 점은 연출이다 (내 판단: 개체별 시뮬레이션보다 단순하고 오프라인 계산과 값이 일치한다).

### 4.3 색 규칙

특정 색은 강화 탭에서 규칙을 열 수 있다. 중반의 단조로움을 깨는 장치.

- 파랑 계열, 번짐: 칸이 완성되면 상하좌우 칸에 작업량 일부가 번진다.
- 노랑 계열, 금빛: 완성 시 물감 방울을 몇 배로 준다.
- 빨강 계열, 열기: 완성 시 몇 초간 모든 요정이 빨라진다.

어느 팔레트 색이 어느 계열인지는 그림 데이터에 표시한다.

### 4.4 강화

물감 방울로 사는 일반 강화: 클릭 힘, 요정 종류별 속도, 칸당 방울, 색 규칙 열기와 강화.

### 4.5 갤러리

완성한 그림마다 영구 보너스(방울 획득 배율)가 붙는다. 갤러리는 프레스티지를 해도 남는다.

### 4.6 프레스티지: 더 고운 눈

- 한 해상도의 그림을 모두 완성하면 다음 해상도로 넘어갈 수 있다.
- 넘어가면 물감 방울, 요정, 일반 강화가 초기화된다.
- 갤러리는 남고, "눈" 재화를 얻는다. 눈으로 영구 강화를 산다: 시작 요정, 오프라인 효율, 전체 속도 배율, 자동 구매.
- 해상도는 8x8, 16x16, 32x32 세 단계.

### 4.7 결말

32x32 그림을 모두 완성하면 그동안의 모든 그림이 타일로 모여 한 장의 큰 모자이크가 되는 장면을 보여 준다. 이후에도 계속 플레이할 수 있지만 새 콘텐츠는 없다.

### 4.8 오프라인 진행

다시 열면 닫혀 있던 시간만큼 요정의 작업량을 계산해 칸과 방울에 반영한다. 최대 인정 시간과 효율은 설정값. 돌아오면 "그동안 몇 칸을 칠했다"는 요약을 띄운다.

### 4.9 저장

브라우저 저장소에 자동 저장(주기는 설정값). 문자열로 내보내기와 가져오기, 초기화는 확인 후 실행. 저장 데이터에 버전 번호를 넣는다.

## 5. 분량과 속도

| 단계 | 그림 수 | 총 칸 수 | 목표 시간 |
|---|---|---|---|
| 8x8 | 8장 | 512 | 약 20분 |
| 16x16 | 8장 | 2,048 | 약 40분 |
| 32x32 | 6장 | 6,144 | 약 60분 이상 |

합계 22장, 약 2시간 이상 (내 판단: 그림 수와 단계별 시간 배분).

그림 주제 (결정): 명화를 픽셀 아트로 옮긴다. 색을 잃은 명화를 복원한다는 설정이 된다.

- 저작권이 끝난 작품만 쓴다 (작가 사후 70년 이상). 피카소, 달리, 마그리트, 워홀 등은 제외.
- 8x8 (내 판단): 구도가 단순해 작은 격자에서도 알아볼 수 있는 작품. 예: 말레비치 검은 사각형, 몬드리안 구성, 호쿠사이 붉은 후지산, 모네 인상 해돋이, 고흐 해바라기.
- 16x16 (내 판단): 인물과 정물. 예: 진주 귀걸이를 한 소녀, 모나리자, 절규, 고흐 자화상.
- 32x32 (내 판단): 풍경과 큰 구도. 예: 별이 빛나는 밤, 가나가와 해변의 큰 파도, 그랑자트섬의 일요일 오후, 수련.
- 그림마다 제목, 작가, 연도를 데이터에 넣고 갤러리에서 보여 준다. 작은 격자에서 알아보기 어려운 약점을 제목이 보완한다.
- 팔레트는 8x8에서 4색, 16x16에서 8색, 32x32에서 최대 16색.

위험: 8x8에서는 명화를 알아보기 어렵다. 알아볼 수 없는 작품은 목록에서 빼고 다른 작품으로 바꾼다.

속도 검증: 화면 없이 게임 규칙만 빠르게 돌리는 시뮬레이션 스크립트를 두고, 단순한 구매 전략(살 수 있으면 가장 싼 것을 산다)으로 끝까지 걸리는 시간이 목표 범위에 드는지 확인한다. 숫자 조정은 이 스크립트를 보면서 한다.

## 6. 그림 데이터 형식

그림은 코드와 분리된 데이터다.

```
{
  id: "apple",
  name: "사과",
  tier: 8,                      // 한 변의 칸 수
  palette: ["#1a1c2c", "#b13e53", "#38b764", "#f4f4f4"],
  traits: { 1: "red" },         // 팔레트 번호별 색 규칙 계열, 없으면 생략
  rows: ["00011000", "00120000", ...]   // 칸마다 팔레트 번호, 16색까지 16진수 한 글자
}
```

나중 확장: PNG를 읽어 이 형식으로 바꾸는 변환기를 추가하면 보유한 그림을 넣을 수 있다. 게임 쪽은 고칠 필요가 없어야 한다. 그러려면 게임이 그림 수, 크기, 색 수를 데이터에서 읽고 어디에도 고정하지 않아야 한다.

## 7. 만드는 방식 (내 판단)

- 프레임워크와 빌드 과정 없음. index.html을 더블클릭하면 실행된다.
- HTML, CSS, 캔버스, 순수 자바스크립트.
- 파일을 나눈다: 게임 규칙(화면을 모름), 화면 그리기와 입력, 설정값, 그림 데이터, 저장.
- 게임 규칙 파일은 브라우저 없이 Node에서도 돌아야 한다. 시뮬레이션과 검사가 이것을 쓴다.
- 모든 균형 숫자(비용, 증가율, 배율, 오프라인 한도, 저장 주기)는 설정 파일 한 곳에 둔다.
- 큰 수는 일반 실수형으로 충분하다. 표시만 줄여 쓴다 (1.2천, 3.4만 식).

## 8. 만드는 사람에게 맡기는 것

- 구체적인 숫자 값. 5장의 목표 시간에 맞추면 된다.
- 22장 그림의 구체적인 도안. 무엇인지 알아볼 수 있어야 한다.
- 화면의 색, 글꼴, 세부 배치. 픽셀 게임다운 느낌이면 된다.
- 요정 점의 움직임 연출.
