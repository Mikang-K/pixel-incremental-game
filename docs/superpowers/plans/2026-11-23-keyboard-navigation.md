# 왼손 키보드 화면 조작 수정 계획

> 계획을 바탕으로 구현했다. 아래 작업 목록은 최초 계획이며, 실제 수행 결과와 미확인 범위는 문서 마지막의 구현 결과에 기록했다.

**Goal:** 휠 없이 왼손 키보드로 확대, 축소, 이동과 전체 보기 복귀를 하고 마우스로 픽셀을 찍을 수 있게 한다.

**Architecture:** 기존 `js/ui.js`의 카메라 함수와 프레임 루프를 재사용한다. 키 상태와 커서 화면 좌표를 입력 처리에 추가하고, 드래그와 포커스 경계에서 상태를 정리한다. 게임 규칙과 저장 형식은 유지한다.

**Tech Stack:** 일반 HTML 스크립트, Canvas 2D, 순수 JavaScript, Node 내장 `node:test`와 `node:vm`. 새 의존성과 빌드 단계 없음.

**Spec:** [왼손 키보드 화면 조작 설계안](../specs/2026-11-23-keyboard-navigation-design.md). 사용자 구현 요청에 따라 제안한 키 배치와 기본 속도를 적용했다.

## Global Constraints

- `index.html`을 직접 열어 실행할 수 있는 기존 구조를 유지한다.
- 키는 `WASD` 이동, `Q/E` 축소/확대, `Shift` 빠른 이동, `F` 전체 보기다.
- 이동 시작값 600 화면 px/초, 빠른 이동 2배, 확대 시작값 2배/초, 카메라 프레임 시간 상한 0.05초를 `CONFIG.ui`에 둔다.
- 설정 입력, 버튼의 기본 키보드 동작, 한글 입력, 브라우저 단축키를 방해하지 않는다.
- 화면 글과 문서는 한글로 작성하고 가운뎃점을 쓰지 않는다.
- 게임 규칙, 저장 데이터와 버전, 그림 데이터는 변경하지 않는다.
- 검사는 저장소 루트에서 `node --test`로 실행한다. Node 검사와 실제 브라우저 검증을 구분해 보고한다.

## Review Focus

1. 드래그 중 카메라 키: 조작을 보류하고 길게 이어지는 오칠을 만들지 않는다. 마우스를 놓은 뒤 새 키 입력을 요구한다. 작업 1에서 검사한다.
2. 키를 누른 채 창 전환, 설정 열기 또는 포커스 변경: 복귀 시 입력이 남아 움직이지 않는다. 작업 1에서 검사한다.
3. 저장 문자열 입력, IME 조합과 브라우저 조합키: 카메라 입력과 분리한다. 작업 1에서 검사한다.
4. 커서 고정 상태의 확대와 이동: 붓 미리보기, 실제 칠하기와 미니맵의 보기 범위가 일치한다. 작업 1의 자동 검사와 작업 2의 브라우저 확인으로 검증한다.
5. 배율 한계, 완료 그림과 프레임 속도 차이: 화면 경계를 유지하고, 완료 뒤에도 탐색하며, 키 반복 설정에 따라 속도가 달라지지 않는다. 작업 1과 2에서 검사한다.

## 파일과 현재 수정 지점

| 파일 | 수정할 부분 |
|---|---|
| `js/ui.js` | 카메라와 좌표 처리(현재 99행), 키보드와 포인터 입력(141행), 설정 열기(355행), `start()`(399행), `frame()`(414행), 탭 숨김 처리(440행) |
| `js/config.js` | 기존 `ui`에 키보드 카메라 조작값 추가 |
| `index.html` | `#view` 포커스, `aria-label`, `#hint` 안내 |
| `README.md` | 기본 조작과 설정 창에서의 동작 안내 |
| `tests/ui.test.js` | 새 UI 입력 회귀 검사 |

현재 `zoomAt()`, `clampCam()`, `fit()`과 `centerOn()`은 `ui.js` 내부에서만 호출된다. 호출부인 휠, 포인터 드래그, 미니맵, 시작과 완료 화면도 회귀 확인 대상이다. 기존 테스트의 `tests/fixtures.js`는 UI 없는 게임 규칙용이므로 기본적으로 수정하지 않는다. CSS에는 이미 캔버스의 `:focus-visible` 스타일이 있어 새 스타일은 필요하지 않다.

## 작업 1: 키보드 카메라 조작과 입력 경계

**Files:** `js/ui.js`, `js/config.js`, `index.html`, 새 `tests/ui.test.js`.

**Interfaces:** 기존 `zoomAt(sx, sy, factor)`, `clampCam()`, `fit()`, `canvasPoint(event)`, `toPixel(sx, sy)`와 `frame(now)`를 사용한다. 새 내부 함수 `updateKeyboardCamera(dt)`는 초 단위 경과 시간을 받고 `cam`만 변경한다. 새 내부 함수 `resetInput()`은 누른 키, `spaceDown`, 드래그 상태를 해제한다. 두 함수 모두 외부로 노출하지 않는다.

- [ ] **1. 입력 회귀 검사를 먼저 추가한다.** `node:vm`에서 실제 `ui.js`, `Game`, `Save`와 기존 `tests/fixtures.js`의 작은 설정/영역을 사용한다. UI 조작 설정은 새 테스트에서만 덧붙인다. 최소 DOM/Canvas 대역을 제공하고 `Image.onload()`를 한 번 호출한 뒤 이벤트 리스너와 예약된 RAF 콜백을 구동한다. 테스트가 검사할 것은 주 캔버스의 `drawImage(display, ox, oy, w, h)` 인수와 `game.paint()` 호출이며, 제품 코드의 문자열 형태나 새 공개 API에 의존하지 않는다.
- [ ] **2. 다음 실패를 확인한다.** `node --test tests/ui.test.js`. 현재 구현에는 `E`, `WASD`, `F` 처리가 없으므로 해당 조작의 카메라 변화 검사가 실패해야 한다.
- [ ] **3. 설정과 프레임 갱신을 추가한다.** `CONFIG.ui`에 `keyboardPanSpeed: 600`, `keyboardFastMultiplier: 2`, `keyboardZoomPerSecond: 2`, `keyboardMaxFrameSeconds: 0.05`를 추가한다. 키다운은 상태를 기록하고 프레임에서 시간을 기준으로 갱신한다. 확대 계수는 `keyboardZoomPerSecond ** (방향 * dt)`다. `F`는 반복 이벤트를 무시하고 다음 프레임에 한 번 처리해 다른 키보다 우선한다.
- [ ] **4. 입력 조건과 정리를 연결한다.** 본문 또는 캔버스 포커스만 허용하고, 설정 창, 편집 요소, IME 조합, `Ctrl/Alt/Meta`를 제외한다. `keyup`은 포커스와 무관하게 해당 키를 정리한다. `blur`, 탭 숨김, 게임 밖 포커스, 설정 열기, `start()`에서 `resetInput()`을 호출한다. 마우스 드래그 시작 시 카메라 키를 비우되 현재 누른 `Space`는 보존해 기존 드래그를 유지한다. 드래그 중 키 반복으로 이동이 재개되지 않게 한다.
- [ ] **5. 포커스와 좌표를 연결한다.** 캔버스에 `tabindex="0"`과 클릭 포커스를 추가한다. `Space`의 허용 타깃에 캔버스를 포함한다. 커서의 화면 좌표를 보관하고 카메라 변경 후 붓의 그림 좌표를 재계산한다. 캔버스 바깥이면 확대 중심은 캔버스 중앙으로 하고 붓 미리보기는 숨긴다.
- [ ] **6. 자동 검사를 통과시킨다.** `node --test tests/ui.test.js`와 `node --test`가 모두 종료 코드 0이어야 한다. 검사 범위는 아래 표와 같다.

| 자동 검사 | 판정 기준 |
|---|---|
| 키 유지와 해제 | 키를 유지하면 여러 프레임에 걸쳐 움직이고, 해제 뒤 추가 이동 없음 |
| 시간과 동시 입력 | 60Hz와 120Hz의 같은 시간 입력 결과가 오차 범위 안에서 같음, Shift는 2배, 대각선 총속도 일정, 반대 키 상쇄 |
| 확대 중심과 한계 | 화면 안 커서의 그림 좌표가 경계 보정 전후 가능한 범위에서 유지, 커서가 밖이면 중앙 기준, 최소/최대 배율 준수 |
| 전체 보기 | `F` 반복으로 재실행하지 않고 `fit()` 결과로 복귀, 같은 프레임의 이동 키보다 우선 |
| 오칠 방지 | 요정 없는 초기 상태에서 카메라 키만으로 `paint()` 호출 없음, 드래그 중 키 입력으로 카메라 변화 없음, 놓은 뒤 새 입력 전 이동 없음 |
| 붓 좌표 | 커서 고정 후 이동/확대한 다음 클릭이 현재 커서 아래의 픽셀을 칠함 |
| 입력 격리 | 설정 열린 상태, textarea/input/contenteditable, 버튼 포커스, IME 조합과 `Ctrl/Alt/Meta`에서 카메라 변화 없음, 기본 이벤트를 취소하지 않음 |
| 한글 자판 | `key`가 한글이어도 조합 중이 아닌 `code: KeyW/KeyQ/KeyE`가 정상 작동 |
| 상태 정리 | blur/탭 숨김/설정 열기/다른 요소 포커스/start 뒤 이전 키가 움직임이나 드래그를 재개하지 않음 |
| 기존 조작 | 휠, 중/우버튼 드래그, 본문과 캔버스에서의 Space+끌기, 미니맵 이동 유지 |
| 완료와 긴 프레임 | 완료 뒤 카메라 탐색 가능, 큰 dt에서도 한 프레임에 0.05초를 넘는 이동 없음 |

## 작업 2: 조작 안내와 실제 브라우저 확인

**Files:** `index.html`, `README.md`. 작업 1에서 만든 키 배치와 입력 조건을 그대로 설명한다.

- [ ] **1. 화면과 문서를 갱신한다.** `#hint`, 캔버스의 접근성 설명, README에 `WASD 이동, Q/E 축소/확대, Shift 빠르게, F 전체 보기`를 적는다. 기존 마우스 조작도 함께 안내한다. 글이 길면 힌트에 줄바꿈을 넣고 최소 화면에서 가려지지 않는지 확인한다.
- [ ] **2. Chrome 또는 Edge에서 실제 입력을 확인한다.** 별도 테스트 프로필의 새 저장으로 `index.html`을 직접 열고 휠을 쓰지 않는다. `E` 확대 → `WASD` 이동 → 픽셀 찍기 → `Q` 축소 → `F` 전체 보기를 수행한다. 일반 한글 자판 상태와 실제 IME 조합 상태를 구분해 확인한다.
- [ ] **3. 회귀를 확인한다.** 설정 창의 입력/복사/붙여넣기, `Tab`과 버튼 활성화, 키를 누른 채 다른 탭이나 창으로 이동 후 복귀, 마우스 드래그 중 카메라 키, 커서 고정 후 붓 미리보기, 미니맵 범위, 완료 그림 탐색을 확인한다. 1280x720과 1920x1080에서 안내와 포커스 표시도 확인한다.
- [ ] **4. 최종 결과를 보고한다.** 자동 검사 결과, 실제 사용한 브라우저, 실행한 조작과 미확인 항목을 분리한다. 기존 사용자 저장에는 손대지 않고 별도 프로필의 테스트 저장만 사용한다.

## 이번 계획 작성에서 확인한 범위

실제 소스, 호출부, 기존 테스트 구조와 문서를 확인했다. 읽기 전용 Node VM 소규모 확인에서 기존 전체 보기 → 휠 2배 확대 → 우클릭 이동의 캔버스 인수가 각각 `[0, 0, 100, 80]`, `[-50, -40, 200, 160]`, `[-40, -35, 200, 160]`으로 변했고 칠한 픽셀 수는 0을 유지했다. 이는 위 자동 검사 방식이 가능하다는 확인이며 새 키보드 기능의 동작 증명은 아니다.

계획 작성 당시에는 구현 작업, 전체 `node --test` 실행과 실제 브라우저 조작 검증을 수행하지 않았다.

## 구현 결과 (2026-11-23)

- 사용자 구현 요청 후 제품 코드와 안내를 수정하고 `tests/ui.test.js`에 UI 회귀 검사 6개를 추가했다. `node --test` 전체 40개 통과, `git diff --check` 통과.
- 독립 리뷰에서 F를 프레임 사이에 짧게 누르면 요청이 사라지는 문제를 발견했다. 별도 일회성 요청으로 수정하고 keydown → keyup → frame 순서의 회귀 검사로 확인했다.
- 별도 저장 컨텍스트의 실제 Chromium 헤드리스 브라우저에서 파일 직접 실행, E 확대, D 이동, 짧은 F 전체 보기, 설정 입력 중 카메라 격리, 캔버스 포커스 복귀와 픽셀 칠하기를 확인했다. 페이지 오류 없음.
- `logs/keyboard-1280.png`와 `logs/keyboard-1920.png`를 캡처했고 1280 화면 안내를 시각 확인했다. 로그는 Git 제외 대상이다.
- 실제 OS 한글 IME, 물리 키보드 조작감, 완료 그림 탐색과 모든 브라우저 회귀 시나리오는 수동 확인하지 않았다. 관련 입력 경계는 Node 대역 검사로 확인한 범위와 구분한다.
